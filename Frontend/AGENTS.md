# AGENTS.md

This file provides guidance to AI coding agents operating in this repository.

## Project Overview

HomeHelper is a tool for parents to keep track of their children's belongings at kindergarden. Parents can log which clothes and items are currently left at kindergarden and what still needs to be brought. Each parent can manage multiple children, and a child can be shared between multiple parents (e.g. both parents of the same child, or across households) so everyone stays in sync.

The frontend is built on a Vite + React + TypeScript boilerplate with comprehensive ESLint configuration, strict TypeScript settings, and development tooling focused on code quality and developer experience.

**Product requirements:** See [REQUIREMENTS.md](../REQUIREMENTS.md) at the repository root for the data model, UI framework choice (Material UI), authentication, child-sharing, backend architecture, and GDPR requirements to implement. Consult and keep it up to date when implementing related features.

**Generated API client:** `src/api/` is generated by an internal client builder tool from the backend. Never create, edit, or delete files in `src/api/` — see [REQUIREMENTS.md](../REQUIREMENTS.md#api-client-generation-client-builder) for details.

**Tech Stack:**

- **Framework:** React 18 with TypeScript (strict mode)
- **Build Tool:** Vite 8 with React plugin
- **Routing:** React Router 7
- **Node Version:** >= 22 (managed via Volta)
- **Head Management:** React Helmet Async
- **Accessibility Testing:** react-axe (dev only, toggle with env variable)

**Import Alias:** `Src/*` → `src/*` (e.g., `import Home from "Src/components/Home/Index"`)

**Testing:** No test infrastructure exists yet. Vitest is the intended framework when tests are added. There are no `vitest.config.*` or `*.test.*`/`*.spec.*` files currently.

## General conventions and patterns

### Naming Conventions

- PascalCase for file names (e.g., `UserProfile.tsx`, `UserService.ts`)
- Write descriptive variable and function names; avoid abbreviations

### Comments

- Keep existing comments unless they are outdated or incorrect
- Document "why" not "what" - code should be self-documenting for "what"

## React conventions and patterns

### Component Structure

- Write components as default export function expressions: `export default function MyComponent() {}`
- ONLY ONE component per file
- Keep components small and focused (Single Responsibility Principle)
- Prefer composition over prop drilling for deeply nested components

#### When to Extract a Component

- Component is reused in 2+ places → Extract
- Component exceeds ~150 lines of code → Consider splitting
- Complex logic unrelated to parent concerns → Extract
- Section of JSX is >30 lines and conceptually distinct → Consider extracting
- Otherwise → Keep inline for simplicity (avoid premature abstraction)
- Avoid deep nesting - if >4 levels, extract child components

### Hooks

- Place custom hooks in separate files
- Always use only one hook per file
